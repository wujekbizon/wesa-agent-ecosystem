- Fixed, sticky, or absolutely positioned UI elements must be designed with strict safe-area constraints and a clear z-index hierarchy, ensuring they never visually obstruct critical content or interactive elements. Always account for their interaction with the document flow and scrolling areas, and ensure they don't functionally override underlying components.
- Avoid fixed viewport heights (`h-screen`, `h-[calc...]`) for main content areas, especially when fixed headers/footers are present. Instead, use flexible height strategies (`min-h-screen`) with appropriate padding and robust scrolling/overflow management to ensure content integrity and prevent collisions on constrained vertical viewports. Always test layouts at common constricted viewport heights.
- Verify that `pointer-events` properties on overlapping or fixed UI elements do not inadvertently create non-interactive "dead zones" that prevent user interaction with underlying content.
- Maintain strict consistency with defined semantic color systems, especially for interactive elements, to avoid confusing users and weakening the visual language.
- Employ variable, deliberate spacing between elements within complex content stacks to clearly articulate hierarchical relationships, ensuring conceptually related items are more proximate. Concurrently, precisely calculate negative space between adjacent elements, particularly positioned ones, to prevent visual tangents and maintain spatial rhythm.
- Ensure all legible text, including micro-typography, meets WCAG AA accessibility standards for contrast and luminosity. Critically, calculate contrast ratios based on the *actual rendered color* and *font size* (e.g., 4.5:1 minimum for 11px text), not merely an opacity percentage, to ensure legibility across devices and for users with visual impairments.
- Never assign hover effects, transition effects, or custom pointer cursors to passive, non-interactive elements, as false affordances destroy predictability and clarity between information and action.
- Primary headings or critical textual information must have sufficient contrast and visual prominence to serve as clear focal points against their background, especially animated or complex ones. Avoid using transparent stroke-only styling on such elements when over intricate or dynamic backgrounds.
- Limit continuous ambient motion to a single visual plane or strictly subordinate its contrast and intensity. Uncoordinated, high-contrast animations across multiple zones create cognitive overload and distract from actionable UI.
- Apply expensive CSS properties like `backdrop-filter: blur()` only when there is high-contrast, complex visual data directly beneath them to refract, ensuring aesthetic value and avoiding wasted rendering cycles.
